## 1. Rôle et position dans le pipeline

### 1.1 Vue d'ensemble

```
 fichiers .ts/.tsx/.js/.jsx (découverte : driver / resolver)
        │
        ▼
 parse oxc (oxc_parser 0.138)  ─►  Program<'a> dans une arène
        │
        ▼
 lowering (src/lowering/*)          ← produit l'IR, seul lecteur de l'AST
        │  ComponentIR / HookIR / FunctionIR / ModuleFacts   (src/ir/*)
        ▼
 resolver::lower_files_with          ← LoweredProgram { components, hooks,
        │                               utilities, file_table, module_table, … }
        ▼
 resolver::analyze_lowered
   ├─ FunctionRegistry / ComponentRegistry (→ ComponentTable) / HookRegistry
   └─ engine::analyze_program ─► analyze_component_impl (par composant)
         ├─ expand_utility_calls   ─┐
         ├─ expand_custom_hooks    ─┴─ splice + remap + α-renommage (src/ir/splice.rs, remap.rs)
         ├─ point fixe (render → effets → handlers → convergence)
         └─ eval_comp_app : analyse des enfants (pas un splice)
        │  ProgramAnalysisResult (render_cfg post-splice, hooks, provenance…)
        ▼
 relations (ProgramRelations, ADR-042) → rules → driver (human/json)
```

L'IR est le **vocabulaire commun** du projet : le lowering l'écrit, le moteur
l'interprète (domaines abstraits), les relations et les règles la relisent
(spans, labels, `AccessPath`, certificats de liaison), et le driver ne
consomme d'elle que les `SourceRange` (via `FileTable`) et les identités
(`ComponentTable`). L'invariant architectural fondateur est posé par ADR-003
(§ Consequences) : *« Abstract domains never see the Oxc AST, only the IR. »*

Toutes les structures de `src/ir/` sont **possédées** (`String`, `PathBuf`,
`Arc<…>`), sans durée de vie liée à l'arène oxc : l'AST est libéré à la fin du
lowering de chaque fichier (`lower_files_with` crée un `Allocator` par fichier,
`src/resolver/mod.rs:247-349`). Elles dérivent toutes `Debug` et `Clone` ; le
moteur clone et réécrit librement (splice, remap).

## 3. Types et structures centraux

### 3.1 Alias de base et `ExprId` (`types.rs`)

`src/ir/types.rs:L1-L25`
```rust
pub type Symbol = String;
pub type HookLabel = usize;
pub type BlockId = usize;
pub type Var = String;

/// A state slot qualified by the component that owns it. `HookLabel` is
/// per-component, so every cross-component fact — a `Versioned` label set, a
/// churn node, a foreign writer row — names a slot this way (ADR-042 §2).
pub type QualifiedSlot = (super::component_id::ComponentId, HookLabel);

/// Allocation-site key. `Ord` so that a walk over a set of sites has one
/// stable order — the first match over a `HashSet<ExprId>` used to depend on
/// the process hash seed (#120).
#[derive(Debug, Clone, Copy, PartialEq, Eq, Hash, PartialOrd, Ord)]
pub struct ExprId(pub usize);

impl ExprId {
    /// Allocate a fresh `ExprId` not derived from any AST node.
    /// Used when creating synthetic heap values during inter-component analysis.
    pub fn fresh() -> Self {
        use std::sync::atomic::{AtomicUsize, Ordering};
        static COUNTER: AtomicUsize = AtomicUsize::new(1_000_000_000);
        ExprId(COUNTER.fetch_add(1, Ordering::Relaxed))
    }
}
```

- `Symbol` et `Var` sont tous deux `String` : `Symbol` nomme des entités
  (composant, champ, hook, tag), `Var` une variable du corps. Aucun typage
  fort ne les distingue.
- `HookLabel` : **indice positionnel** d'un hook dans *un* composant (0, 1, 2…
  dans l'ordre d'extraction). C'est l'image directe de la règle des hooks de
  React (l'identité d'un hook = son rang d'appel). Il n'est pas global : deux
  composants ont chacun un label 0. D'où `QualifiedSlot = (ComponentId,
  HookLabel)` pour tout fait inter-composant.
- `BlockId` : identifiant de bloc dans *un* CFG.
- `ExprId` : **site d'allocation** (ADR-010) porté par `ObjectLit`, `ArrayLit`,
  `FnLit`, `New` et `SummaryValue::Shape`. Clef du tas abstrait. `Ord` depuis
  #120 (déterminisme). `fresh()` puise dans un compteur global commençant à
  10⁹ pour ne jamais croiser les ids issus du lowering (utilisé pour l'objet
  `props` synthétique d'un enfant, `src/domains/transfer/state_value.rs:563`,
  et dans `src/engine/written.rs:300,324,339`).
- Qui fabrique les `ExprId` du lowering : `ExprIds`, un `Rc<Cell<usize>>`
  partagé par tous les corps d'**un appel de lowering par fichier**
  (`src/lowering/cfg_builder.rs:20-42`) ; il est cloné dans chaque
  `BlockBuilder` via `LowerCtx`. Conséquence observée : les composants d'un
  même fichier partagent un compteur, mais un hook custom est abaissé par un
  autre appel (`lower_custom_hooks_with_resolver`) et **recommence à 0** —
  d'où la nécessité de `Offsets::ids` au splice (§4.5).

### 3.2 Positions : `FileId`, `FileTable`, `SourceRange`, `SourceMap` (`source_range.rs`)

`src/ir/source_range.rs:L3-L49`
```rust
/// Identity of a source file, interned in a [`FileTable`] (ADR-019).
///
/// 4 bytes and `Copy`, so [`SourceRange`] stays `Copy` while carrying file
/// identity — the fix for the ADR-011 limitation where a span inside a
/// cross-file inlined CFG could not name the file it points into.
#[derive(Debug, Clone, Copy, PartialEq, Eq, Hash, PartialOrd, Ord)]
pub struct FileId(u32);

/// Interning table `FileId ↔ PathBuf`, built once during lowering (one entry
/// per parsed file) and carried through to the renderers.
#[derive(Debug, Default, Clone)]
pub struct FileTable {
    paths: Vec<PathBuf>,
}

impl FileTable {
    /// Intern `path`, returning the existing id when already present.
    pub fn intern(&mut self, path: &Path) -> FileId {
        if let Some(i) = self.paths.iter().position(|p| p == path) {
            return FileId(i as u32);
        }
        self.paths.push(path.to_path_buf());
        FileId((self.paths.len() - 1) as u32)
    }

    /// Resolve an id minted by [`FileTable::intern`]. `None` only when the id
    /// comes from another table (or [`SourceMap::empty`], which never mints
    /// spans).
    pub fn path(&self, id: FileId) -> Option<&Path> {
        self.paths.get(id.0 as usize).map(PathBuf::as_path)
    }
}

/// A `(file, line, col)` source position. `line` is 1-indexed, `col` 0-indexed.
#[derive(Debug, Clone, Copy, PartialEq, Eq, Hash)]
pub struct SourceRange {
    pub file: FileId,
    pub line: u32,
    pub col: u32,
}

impl SourceRange {
    /// `(line, col)` sort key for ordering diagnostics within a file.
    pub fn pos_key(&self) -> (u32, u32) {
        (self.line, self.col)
    }
}
```

`src/ir/source_range.rs:L51-L102`
```rust
/// Everything the lowering needs to mint [`SourceRange`]s for one file:
/// the line-start table plus the file's interned identity.
#[derive(Debug, Clone)]
pub struct SourceMap {
    line_starts: Vec<u32>,
    file: FileId,
}

impl SourceMap {
    pub fn new(source: &str, file: FileId) -> Self {
        Self {
            line_starts: compute_line_starts(source),
            file,
        }
    }

    /// Map with no line table: `span_at` always yields `None`. For manual-IR
    /// tests that don't care about spans.
    pub fn empty() -> Self {
        Self {
            line_starts: Vec::new(),
            file: FileId(u32::MAX),
        }
    }

    /// Convert a byte offset into a span, `None` when the map is empty.
    pub fn span_at(&self, offset: u32) -> Option<SourceRange> {
        (!self.line_starts.is_empty())
            .then(|| offset_to_range(&self.line_starts, offset, self.file))
    }
}

/// Build a table of byte offsets where each line begins (index = line index, value = start offset).
pub fn compute_line_starts(source: &str) -> Vec<u32> {
    let mut starts = vec![0u32];
    for (i, b) in source.bytes().enumerate() {
        if b == b'\n' {
            starts.push(i as u32 + 1);
        }
    }
    starts
}

/// Convert a byte offset into a 1-indexed (line, col) pair using a pre-built line-starts table.
pub fn offset_to_range(starts: &[u32], offset: u32, file: FileId) -> SourceRange {
    let line = starts.partition_point(|&s| s <= offset).saturating_sub(1);
    SourceRange {
        file,
        line: line as u32 + 1,
        col: offset - starts[line],
    }
}
```

Points à retenir :

- Un `SourceRange` est **un point**, pas un intervalle (malgré le nom) :
  `(file, line, col)`. `line` 1-indexé, `col` 0-indexé. `col` est une
  différence d'**octets** UTF-8 (les offsets oxc sont des octets) : sur une
  ligne contenant des caractères non ASCII avant la position, la colonne
  affichée est en octets, non en caractères (déduit du code ; non testé).
- `FileId` n'a **pas** de constructeur public : seul `FileTable::intern` en
  fabrique (et `SourceMap::empty` utilise la valeur réservée `u32::MAX`, qui
  n'est jamais résolue). `intern` est une recherche linéaire (O(F) par appel,
  O(F²) sur un run) — sans importance à l'échelle d'un projet.
- Les spans d'un corps splicé gardent le `FileId` du fichier où ils ont été
  abaissés : c'est ce qui permet au rendu d'ADR-024 de nommer le fichier
  d'origine « avec zéro logique dans le splice » (ADR-019 §1).
- `partition_point` (et non `binary_search` comme l'écrit ADR-011) : O(log L).
- `SourceRange` n'implémente pas `Ord` ; l'ordre intra-fichier passe par
  `pos_key`.

### 3.3 Le CFG (`cfg.rs`)

`src/ir/cfg.rs:L5-L65`
```rust
#[derive(Debug, Clone)]
pub struct BasicBlock {
    pub id: BlockId,
    pub stmts: Vec<Stmt>,
    pub term: Terminator,
}

#[derive(Debug, Clone)]
pub enum Terminator {
    Jump(BlockId),
    Branch {
        cond: Expr,
        then_: BlockId,
        else_: BlockId,
        /// Where the condition is evaluated in the source (None for
        /// synthetic branches and manual-IR tests).
        span: Option<crate::ir::SourceRange>,
    },
    /// Unlike [`Terminator::Branch`], this carries no span: nothing needed the
    /// position of a `return` until a hook could be extracted from one (#4),
    /// and adding it now is a 40-site IR change tracked separately. The cost is
    /// that a hook reached only through a return yields findings with no line
    /// number — visible but unlocated, which is still strictly better than the
    /// silence it replaced.
    Return(Expr),
    Unreachable,
}

#[derive(Debug, Clone, PartialEq, Eq)]
pub enum EdgeKind {
    Unconditional,
    IfTrue,
    IfFalse,
    Back,
    /// The split at an `await` (#117, ADR-035). Control is the same — the edge
    /// is unconditional — but the successor runs on a later turn of the event
    /// loop, so `sync_phase`'s "lexis = execution, provably" stops holding
    /// across it. Consumers ask [`CFG::post_await_blocks`] rather than reading
    /// this variant directly.
    Await,
}

#[derive(Debug, Clone)]
pub struct Edge {
    pub from: BlockId,
    pub to: BlockId,
    pub kind: EdgeKind,
}

/// The block map is a [`BTreeMap`], not a `HashMap`, on purpose: every walk
/// over `blocks` then visits them in ascending [`BlockId`] — i.e. lowering
/// order — so a pass that picks a *representative* block (the first setter
/// call site of a witness, say) reports the same one on every run. Under a
/// `HashMap` that choice followed the per-process hash seed and diagnostics
/// were not reproducible.
#[derive(Debug, Clone)]
pub struct CFG {
    pub entry: BlockId,
    pub blocks: BTreeMap<BlockId, BasicBlock>,
    pub edges: Vec<Edge>,
}
```

Champ par champ :

- `BasicBlock.id` : doit égaler la clé de la `BTreeMap` (vérifié par
  `validate`). `stmts` : séquence linéaire. `term` : un seul terminateur.
- `Terminator::Jump(t)` : saut inconditionnel. `Branch { cond, then_, else_,
  span }` : `cond` est une expression (souvent `Var("__tN")` pour les
  diamants `&&`/`||`, cf. ADR-020 non-changement n°1). `Return(e)` : **sans
  span** (issue #140 ouverte). `Unreachable` : le contrôle ne continue pas
  (`throw`, `break` orphelin) ; *jamais* une chute en fin de corps, qui est
  `Return(Lit(Unit))` depuis `34ce48b` (`BlockBuilder::into_cfg`,
  `src/lowering/cfg_builder.rs:213-240`).
- `EdgeKind` : `Unconditional`, `IfTrue`/`IfFalse` (servent au narrowing),
  `Back` (sert au widening, ADR-014), `Await` (frontière de phase, ADR-035).
- `CFG.edges` est **la** source de vérité pour la navigation : `successors` et
  `predecessors` lisent `edges`, pas les terminateurs. Un terminateur sans
  arête correspondante est invisible au worklist (d'où la clause 3 de
  `validate`).
- `blocks: BTreeMap` : ordre déterministe (#86, #120, commit `6e9dc35`).

**Invariant implicite de densité.** Le lowering alloue les blocs par un
compteur (`BlockBuilder::new_block`, `counter` commençant à 1, bloc 0 =
entrée ; `src/lowering/cfg_builder.rs:103-116,156-160`) et le splice place les
blocs de l'appelé à `max+1 … max+n` et la jointure à `max+n+1` : les ids d'un
CFG sont donc `0..len` sans trou. Cet invariant n'est ni documenté ni
`debug_assert`é, mais `splice_callee_into_cfg` en dépend (le bloc de jointure
est `block_offset + callee_block_map.len()`, §4.6). Vérifié empiriquement avec
la sonde sur 930 CFG des fixtures et 5 512 CFG de cinq corpus (shadcn-admin,
bulletproof-react, commerce, zustand, memos) : aucun trou.

```rust
pub enum Stmt {
    Let {
        var: Var,
        rhs: Expr,
        span: Option<SourceRange>,
    },
    Assign {
        var: Var,
        rhs: Expr,
        span: Option<SourceRange>,
    },
    /// In-place write through a member expression: `obj.f = v`, `arr[i] = v`,
    /// `obj.f++`, `delete obj.f`. The heap identity of `obj` is unchanged —
    /// that is the semantic payload: a mutation, not a rebinding.
    MemberWrite {
        obj: Expr,
        key: MemberKey,
        rhs: Expr,
        span: Option<SourceRange>,
    },
    ExprStmt(Expr, Option<SourceRange>),
}

impl Stmt {
    /// Where the statement is in the source, whichever variant it is.
    ///
    /// `None` for a statement lowering or the splice synthesised and could not
    /// place — every such site is meant to place what it mints (ADR-039), so a
    /// `None` here is a bug to fix, not a shape to route around.
    pub fn span(&self) -> Option<SourceRange> {
        match self {
            Stmt::Let { span, .. }
            | Stmt::Assign { span, .. }
            | Stmt::MemberWrite { span, .. }
            | Stmt::ExprStmt(_, span) => *span,
        }
    }
}

/// Which member of the object a [`Stmt::MemberWrite`] targets. `Index` keeps
/// the index expression alive: it is evaluated at runtime, so its reads count
/// (free variables, callbacks).
#[derive(Debug, Clone)]
pub enum MemberKey {
    Field(Symbol),
    Index(Expr),
}
```

- `Let` vs `Assign` : la distinction est **sémantique** pour le splice.
  `Let` introduit une liaison locale ; un `Assign` sans `Let` du même nom est
  « l'orthographe IR d'une écriture dans une liaison extérieure »
  (`src/ir/splice.rs:160-163`). `bound_vars` (§4.7) ne compte que les `Let`,
  tandis que `compute_free_vars` retire `Let` **et** `Assign` des lectures
  libres (asymétrie discutée §8).
- `MemberWrite` : mutation en place, identité de tas inchangée. Produit pour
  `obj.f = v`, `arr[i] = v`, `obj.f++` (rhs opaque), `delete obj.f` (rhs
  `Lit(Unit)`), `src/lowering/expr_lower.rs:209,282,293,1124`.
- `ExprStmt` : expression évaluée pour ses effets. Observation (sonde) : une
  affectation membre en position instruction `document.title = String(total);`
  produit un `MemberWrite` **puis** un `ExprStmt(String(total))` — la valeur de
  l'expression d'affectation est ré-émise comme instruction. Cause (vérifiée) :
  le bras `Expression::AssignmentExpression` de `lower_expr` pousse le
  `MemberWrite` puis **renvoie la valeur** de l'affectation (`value` = le rhs
  abaissé pour un `=` simple, `src/lowering/expr_lower.rs:519-535`), et le
  bras `Statement::ExpressionStatement` du builder enveloppe toujours cette
  valeur dans un `ExprStmt` (`src/lowering/cfg_builder.rs:286-289`). Même
  mécanisme pour une cible identifiant : `x = e;` donne `Assign { x, e }` puis
  `ExprStmt(Var(x))` (`:511-516`). Sans effet sur la soundness : l'appel est
  sur-compté, pas perdu.
- `span` : tous les variants en ont un (`Option`). ADR-039 impose qu'un
  statement synthétique prenne la position de l'expression qu'il lie ; le
  `None` résiduel est qualifié de bug. Résidu observé : le `let __obj_N =
  __p0` produit pour un paramètre déstructuré (`function C({ x })`) est
  imprimé sans span par la sonde (exemples §6.2, §6.4). Cause (vérifiée) :
  `inject_param_preamble` appelle `lower_binding_pattern(other,
  Expr::Var(temp), None, builder)` (`src/lowering/cfg_builder.rs:963-965`) ;
  le `Let` du temporaire reçoit ce `span` nul
  (`src/lowering/cfg_builder.rs:895-900`), tandis que chaque propriété est
  placée par `builder.span_at(prop.span.start).or(span)` (`:925`). C'est donc
  un résidu non placé au sens d'ADR-039 (aucun commentaire ne le déclare
  volontaire) ; la conséquence est bénigne (ce `Let` ne porte qu'une copie de
  variable).

#### 3.5.2 Aides sur les objets et mutations

`src/ir/expr.rs:L82-L113`
```rust
/// Key prefix lowering gives the synthetic `ObjectLit` member that holds an
/// object spread (`{ ...opts }`). A spread's own members are invisible to the
/// per-member map, and it overwrites every member written before it, so a
/// reader that resolves members by name must stop at one. Source keys can
/// never collide — `...` is not a valid property name.
pub const SPREAD_KEY_PREFIX: &str = "...";

/// The suffix of `fields` a name lookup may read: everything after the last
/// spread. Members written before one may have been overwritten by something
/// the per-member map cannot see, so they answer nothing.
///
/// Shared so the two readers that resolve members by name cannot drift apart
/// on the rule — the abstract interpreter's `obj_members` and the binding
/// chase in [`crate::engine::seeds`].
pub fn members_after_last_spread(fields: &[(Symbol, Expr)]) -> &[(Symbol, Expr)] {
    let start = fields
        .iter()
        .rposition(|(k, _)| k.starts_with(SPREAD_KEY_PREFIX))
        .map_or(0, |i| i + 1);
    &fields[start..]
}

/// The expression bound to `key` in an object literal, exactly — `None` when
/// no readable member has that name, which includes every member a spread may
/// have overwritten.
pub fn object_member<'e>(fields: &'e [(Symbol, Expr)], key: &str) -> Option<&'e Expr> {
    members_after_last_spread(fields)
        .iter()
        .rev()
        .find(|(k, _)| k == key)
        .map(|(_, v)| v)
}
```

Soundness : un membre écrit **avant** un spread peut avoir été écrasé par le
spread, donc il « ne répond rien » (et non « répond sa valeur ») ; la
recherche `rev()` retient la **dernière** écriture d'une clé dupliquée
(sémantique JS). `MUTATING_METHODS` (`src/ir/expr.rs:121-135`) est la liste
unique `push, pop, shift, unshift, splice, sort, reverse, fill, copyWithin,
add, delete, clear, set` partagée par `state-mutation`, la garde de pureté
Tier-A et la dépendance de rendu (ADR-028 §2) ; `mutation_receiver`
(`:143-158`) renvoie le receveur muté d'un appel `x.push(…)` ou le premier
argument de `Object.assign(t, …)`.

```rust
/// What a [`Expr::HookMarker`] binding reads as.
///
/// The distinction is decided at lowering, where "is this React's own hook?"
/// is still known: a React hook with no tracked result really does return
/// `undefined`, while an unresolved custom hook returns something the engine
/// has no information about. Collapsing the two — as a single `undefined`
/// once did — makes an opaque hook's return *provably stable*
/// (`to_stability` joins `Stable` for `undef`), which silences every
/// stability-gated rule on it: a false negative, and the forbidden direction.
#[derive(Debug, Clone, PartialEq, Eq)]
pub enum MarkerVal {
    /// Reads as `undefined` — React's own value-less hooks (an effect returns
    /// nothing).
    Undefined,
    /// Reads as a reference whose identity is constant across renders —
    /// `useRef`. Reading it as `Undefined` instead was *stable enough* for the
    /// deps rules (`to_stability` joins `Stable` for `undef` too), but it threw
    /// the identity away: the container is a reference, and every rule that
    /// reasons about references rather than about stability saw nothing there.
    StableRef,
    /// Reads as ⊤ — a custom hook the engine could neither inline nor
    /// summarize. Paired with the `analysis-limit/unknown-hook` Info.
    Unknown,
    /// Reads as the library hook's [`HookSummary`](crate::registry::HookSummary).
    /// Retagged onto the marker by `expand_custom_hooks` rather than replacing
    /// it: overwriting the marker with a bare `SummaryVal` erased the label,
    /// and with it the call site every rules-of-hooks check needs — a
    /// conditional `useAtom()` was invisible to `conditional-hook`.
    Summary(SummaryValue),
}
```

```rust
    /// ⊤ completely unknown; default for hooks without a precise summary.
    Top,
    /// Hook returns a reference-stable value (safe as a `useEffect` dep).
    StableRef,
    /// Hook returns a reference-unstable value (new object/array every render).
    UnstableRef,

    /// it: `form.handleSubmit(onSubmit)` returns an event handler and calls
    /// `onSubmit` only when that handler fires.
    ///

    /// separate claim about a separate thing: react-hook-form's `handleSubmit`
    /// is `useCallback`-backed, `@mantine/form`'s `onSubmit` is a fresh arrow
    /// every render, and both wrap. Riding the timing on the value would make
    /// the mantine entry claim a stability nobody promised.
    Wrapper { stable: bool },

    ///

    /// `useForm()` guarantees `setValue` and `reset` are the same function at
    /// every render while `formState` is a Proxy that is not. So the container
    /// stays ⊤ — a member the list does not name answers ⊤ too, which is what
    /// keeps an unlisted member from being credited with a stability nobody
    /// promised.
    ///

    /// site when the marker is retagged, so two calls of one hook are two
    /// objects (#134).

    /// value as holding still across the loop.

    /// `useSearchParams` tuple (#161). A call through it in a body the loop
    /// can run moves every [`Self::Held`] value. `stable` is its own
    /// identity across renders, a separate claim: Next documents the router
    /// object's methods stable, react-router's `navigate` and
    /// `setSearchParams` change with the location outside a data router.
    Navigator { stable: bool },
```

```rust
/// How many entries a written deps array has.
///
/// Elisions and spreads are not the same kind of ignorance, and collapsing them
/// cost real findings. An elision drops an element from `elems` but the source
/// array's length is still perfectly countable at lowering (`[a, , b]` has
/// three entries), so the arity stays **exact**. Only a spread is open-ended:
/// `[a, ...rest]` holds one entry plus however many `rest` does, which is a
/// lower bound and nothing more.
#[derive(Debug, Clone, Copy, PartialEq, Eq)]
pub enum Arity {
    /// The source array holds exactly this many entries.
    Exact(usize),
    /// The source array holds at least this many; a spread supplies the rest.
    AtLeast(usize),
}

impl Arity {
    /// The count when it is known, `None` when a spread left it open.
    pub fn exact(self) -> Option<usize> {
        match self {
            Arity::Exact(n) => Some(n),
            Arity::AtLeast(_) => None,
        }
    }

    /// The guaranteed lower bound — always available, and what lets an
    /// open-ended list still *refute* an arity claim.
    pub fn at_least(self) -> usize {
        match self {
            Arity::Exact(n) | Arity::AtLeast(n) => n,
        }
    }

    /// Could the source array hold exactly `n` entries? `false` only when the
    /// bound refutes it — an open-ended list may still grow to any count above
    /// its own.
    pub fn may_be(self, n: usize) -> bool {
        match self {
            Arity::Exact(m) => m == n,
            Arity::AtLeast(m) => m <= n,
        }
    }
}
```

`Arity` est un petit treillis : `Exact(n)` ⊑ `AtLeast(n)` (concrétisations
`{n}` ⊆ `{n, n+1, …}`) ; `may_be` est le test d'appartenance à la
concrétisation, `at_least` le minorant. Aucun `join` n'est défini (non
nécessaire : l'arité est un fait syntaxique d'un site).

```rust
/// The deps argument of a hook call, as the IR could read it.
///
/// The three states are three different facts, and folding any two of them
/// together has cost findings in both directions:
///
/// - [`DepsArg::Absent`] — no argument at all. The hook re-runs on every
///   render, so nothing it captures can go stale.
/// - [`DepsArg::Opaque`] — an argument the IR cannot read (`useMemo(fn, deps)`).
///   The hook **is** gated by a list, so its captures can go stale exactly like
///   a declared-but-incomplete array; the engine simply cannot see one element
///   of it. Reading this as `Absent` skips the hook; reading it as an empty
///   list claims it declares nothing. Both are wrong, in opposite directions.
/// - [`DepsArg::List`] — a written array literal, with whatever the lowering
///   could keep of it.
#[derive(Debug, Clone)]
pub enum DepsArg {
    Absent,
    Opaque,
    List(DepsList),
}

impl DepsArg {
    /// The deps argument of `expr`: a written array literal becomes a list,
    /// anything else is opaque. TS annotations are peeled first — `[a] as const`
    /// is an array literal to everyone except a bare pattern match.
    pub fn from_expr(expr: Expr) -> Self {
        match expr.peel_ts_owned() {
            Expr::ArrayLit {
                elems,
                arity,
                spread_at,
                ..
            } => DepsArg::List(DepsList {
                elems,
                arity,
                spread_at,
            }),
            _ => DepsArg::Opaque,
        }
    }

    /// The entries that actually cover a read — [`DepsList::covering`], empty
    /// when no list was written. What a *suppression* must ask for: a
    /// flattened `[...rows]` declares `rows[0], rows[1], …`, never `rows`.
    pub fn covering(&self) -> std::borrow::Cow<'_, [Expr]> {
        self.list()
            .map_or(std::borrow::Cow::Borrowed(&[][..]), DepsList::covering)
    }

    /// The written list, when there is one to read.
    pub fn list(&self) -> Option<&DepsList> {
        match self {
            DepsArg::List(l) => Some(l),
            DepsArg::Absent | DepsArg::Opaque => None,
        }
    }

    /// `true` unless the caller passed no deps argument at all. An unreadable
    /// argument still declares a deps array — the caller wrote one, and saying
    /// otherwise puts "this effect re-runs after every render" on a gated hook.
    pub fn is_declared(&self) -> bool {
        !matches!(self, DepsArg::Absent)
    }

    pub fn map_exprs(self, f: impl FnMut(Expr) -> Expr) -> Self {
        match self {
            DepsArg::List(l) => DepsArg::List(l.map_exprs(f)),
            other => other,
        }
    }
}
```

```rust
/// A written dependency array, with whatever lowering could keep of it.
///
/// `elems` holds the elements the IR can see: an elision contributes none, and
/// a spread contributes its *source* as one element standing for however many
/// it holds. `arity` says how long the source array actually is.
///
/// Enumerating `elems` is sound whenever the enumeration makes a rule **fire** —
/// each element over-approximates what it stands for. It is NOT sound when the
/// enumeration makes a rule *stop*: crediting `[...rows]` as declaring `rows`
/// suppresses a stale-capture finding React itself would report, because React
/// compares `rows[0], rows[1], …` and never `rows`.
#[derive(Debug, Clone)]
pub struct DepsList {
    pub elems: Vec<Expr>,
    pub arity: Arity,
    /// Positions in `elems` that came from a spread — see
    /// [`DepsList::covering`], which is the reason the field exists.
    pub spread_at: Vec<usize>,
}

impl DepsList {
    /// A list whose elements are known one-for-one — every literal `[a, b]`,
    /// and every hand-built IR fixture.
    pub fn exact(elems: Vec<Expr>) -> Self {
        let n = elems.len();
        DepsList {
            elems,
            arity: Arity::Exact(n),
            spread_at: vec![],
        }
    }

    /// The entries that actually **cover** a read — every visible element
    /// except a spread's source.
    ///
    /// This is the line between the two ways a rule uses a deps list. Reading
    /// `elems` to make a rule *fire* is sound however the list was truncated,
    /// because each element over-approximates what it stands for. Reading it
    /// to make a rule *stop* is not: React compares `rows[0], rows[1], …` and
    /// never `rows`, so crediting a flattened `[...rows]` as declaring `rows`
    /// suppresses a stale capture React itself reports. The elements written
    /// beside the spread still cover their own reads, which is why this
    /// filters rather than refusing the whole list.
    pub fn covering(&self) -> std::borrow::Cow<'_, [Expr]> {
        if self.spread_at.is_empty() {
            return std::borrow::Cow::Borrowed(&self.elems);
        }
        std::borrow::Cow::Owned(
            self.elems
                .iter()
                .enumerate()
                .filter(|(i, _)| !self.spread_at.contains(i))
                .map(|(_, e)| e.clone())
                .collect(),
        )
    }
```

C'est l'un des passages les plus instructifs du projet pour la soundness :
**la même donnée se lit différemment selon qu'elle fait tirer ou taire une
règle**. `elems` sert à *tirer* (chaque élément sur-approxime), `covering()`
sert à *supprimer* (seuls les éléments réellement comparés par React). Le
moteur appelle `free_paths_and_pinned(body_cfg, &deps.covering())`
(`src/engine/fixpoint.rs:1435`) : l'épinglage n'utilise jamais un spread.
`is_whole()` (`:220-222`) teste `arity == Exact(elems.len())`.
Les autres méthodes publiques de `DepsList` (`src/ir/hooks.rs:224-245`) :
`map_exprs` réécrit chaque élément **en conservant `arity` et `spread_at`**
(c'est par elle que remap, α-renommage et substitution traversent les deps
sans changer ce que le source contenait) ; `as_slice`, `len`, `is_empty`
sont de simples accesseurs sur `elems` (donc sur les éléments *visibles*,
pas sur la longueur source). `DepsArg::map_exprs` (`:152-157`) délègue à
`DepsList::map_exprs` et laisse `Absent`/`Opaque` intacts. Enfin

```rust
/// Interning table `ComponentId ↔ (file, name)`, built once from the component
/// registry and carried on the analysis result.
///
/// It also owns [`Self::display_name`], because minting that string needs the
/// collision counts and nothing else does. Keeping the two together is what
/// stops a second, disagreeing spelling from being invented elsewhere.
#[derive(Debug, Default, Clone)]
pub struct ComponentTable {
    /// A map, not a vector indexed by id: a result analysed before any table
    /// existed carries [`ComponentId::SYNTHETIC`], and registering *that* id
    /// is how such a result joins a program without its interior labels
    /// having to be rewritten.
    origins: HashMap<ComponentId, CompOrigin>,
    by_origin: HashMap<CompOrigin, ComponentId>,
    next: u32,
    /// How many files define each bare name — the only input to
    /// [`Self::display_name`], precomputed because that answer is asked once
    /// per rendered finding.
    name_counts: HashMap<String, usize>,
}

impl ComponentTable {
    /// Intern `origin`, returning the existing id when already present.
    pub fn intern(&mut self, origin: CompOrigin) -> ComponentId {
        if let Some(id) = self.by_origin.get(&origin) {
            return *id;
        }
        let id = ComponentId(self.next);
        self.next += 1;
        self.register(id, origin);
        id
    }

    /// Record `origin` under an id that already exists.
    ///
    /// For the one case that cannot go through [`Self::intern`]: a result
    /// analysed on its own carries [`ComponentId::SYNTHETIC`] in its state
    /// labels and its setter owners, so the table has to accept that id rather
    /// than mint a new one the labels would not match.
    pub fn register(&mut self, id: ComponentId, origin: CompOrigin) {
        if self.origins.contains_key(&id) {
            return;
        }
        *self.name_counts.entry(origin.name.clone()).or_default() += 1;
        self.by_origin.insert(origin.clone(), id);
        self.origins.insert(id, origin);
    }
```

```rust
        match self {

            | Expr::Var(_)
            | Expr::FnLit { .. }
            | Expr::StateVal(_)
            | Expr::StateSetter(_)
            | Expr::MemoVal(_)
            | Expr::CallbackVal(_)

                for e in elems {

                }
            }
            Expr::FieldAccess { obj, .. } => f(obj),
            Expr::IndexAccess { arr, idx } => {
                f(arr);
                f(idx);

                f(lhs);
                f(rhs);
```

```rust
            for stmt in block.stmts.iter().filter(|s| keep(s)) {
                match stmt {

                    | crate::ir::stmt::Stmt::Assign { rhs, .. } => f(rhs),

                        f(obj);

                            f(idx);
                        }
                        f(rhs);

                }

            match &block.term {

                Terminator::Jump(_) | Terminator::Unreachable => {}
```

```rust
    /// Blocks whose execution is separated from the entry by at least one
    /// `await` in THIS body (#117).
    ///
    /// The reachable closure from every `Await` edge's target, so a loop whose
    /// body awaits marks its own header — the second iteration does run after a
    /// suspension. Empty for a body with no `await`, which is the common case
    /// and costs one `edges` scan to find out.
    ///
    /// Nested function bodies are separate CFGs and answer for themselves: an
    /// `await` in a callback does not defer the caller's later statements.
    pub fn post_await_blocks(&self) -> std::collections::HashSet<BlockId> {
        let mut out = std::collections::HashSet::new();
        let seeds: Vec<BlockId> = self
            .edges
            .iter()
            .filter(|e| e.kind == EdgeKind::Await)
            .map(|e| e.to)
            .collect();
        if seeds.is_empty() {
            return out;
        }
        let mut queue: std::collections::VecDeque<BlockId> = seeds.into_iter().collect();
        while let Some(b) = queue.pop_front() {
            if !out.insert(b) {
                continue;
            }
            for succ in self.successors(b) {
                if !out.contains(&succ) {
                    queue.push_back(succ);
                }
            }
        }
        out
    }

    /// Blocks reachable from [`Self::entry`] by following edges.
    ///
    /// Splicing and `if`/`else` lowering both leave orphan blocks behind (a
    /// join whose every predecessor returned, an inlined body after a `throw`),
    /// so "every block of the CFG" and "every block that can execute" are not
    /// the same set. Anything quantifying over program points — exits above
    /// all — must use this one.
    pub fn reachable_blocks(&self) -> std::collections::HashSet<BlockId> {
        let mut seen = std::collections::HashSet::new();
        let mut stack = vec![self.entry];
        while let Some(id) = stack.pop() {
            if !seen.insert(id) {
                continue;
            }
            stack.extend(self.successors(id));
        }
        seen
    }
```

- `post_await_blocks` : BFS depuis les cibles des arêtes `Await`. Soundness :
  sur-approxime « exécuté après une suspension » (tout bloc atteignable
  depuis un `await`, y compris l'en-tête d'une boucle qui attend). Un `await`
  dans un callback imbriqué n'affecte que le CFG du callback.
- `reachable_blocks` : DFS depuis `entry`. Pour **quantifier** sur des points
  de programme (« sur tous les chemins jusqu'à la sortie »), il faut
  l'utiliser : un bloc orphelin (jointure dont tous les prédécesseurs
  retournent) ne doit pas compter comme une sortie.
- Complexité : `successors` est un balayage linéaire de `edges` (O(E) par

  Les CFG sont petits ; pas d'index d'adjacence.

```rust
    /// that rewrites blocks and edges (splicing, remapping).
    ///
    /// Returns the first violation as prose, or `Ok(())`. Three things have to
    /// hold for the engine to see the whole program:
    ///
    /// 1. The entry block exists — without it nothing is analysed at all.
    /// 2. Every terminator target names a block that exists — a dangling target
    ///    is code the fixpoint silently never enters.
    /// 3. Every terminator target also has an edge. `successors` reads `edges`,
    ///    not terminators, so a target with no edge is invisible to the
    ///    worklist even though the block is there.
    ///
    /// Cheap enough to run under `debug_assert!` but linear in edges per block,
    /// so it stays out of release builds.
    pub fn validate(&self) -> Result<(), String> {
        if !self.blocks.contains_key(&self.entry) {
            return Err(format!("entry block {} is missing", self.entry));
        }
        for edge in &self.edges {
            if !self.blocks.contains_key(&edge.from) {
                return Err(format!("edge from missing block {}", edge.from));
            }
            if !self.blocks.contains_key(&edge.to) {
                return Err(format!("edge to missing block {}", edge.to));
            }
        }
        for (&id, block) in &self.blocks {
            if block.id != id {
                return Err(format!("block keyed {} reports id {}", id, block.id));
            }
            let targets: Vec<BlockId> = match &block.term {
                Terminator::Jump(t) => vec![*t],
                Terminator::Branch { then_, else_, .. } => vec![*then_, *else_],
                Terminator::Return(_) | Terminator::Unreachable => vec![],
            };
            for t in targets {
                if !self.blocks.contains_key(&t) {
                    return Err(format!("block {id} targets missing block {t}"));
                }
                if !self.edges.iter().any(|e| e.from == id && e.to == t) {
                    return Err(format!("block {id} targets {t} with no edge"));
                }
            }
        }
        Ok(())
    }
```

```rust
/// Extract the maximal member chain rooted at a variable, pushing any
/// off-chain sub-expressions (index expressions, non-variable bases) into
/// `side` for the caller to recurse into. Returns `(root, segments, opaque)`
/// where `opaque` marks a dynamic index encountered in the chain (segments
/// are then meaningless — collapsed to the bare root).
fn extract_path<'e>(e: &'e Expr, side: &mut Vec<&'e Expr>) -> Option<(Var, Vec<String>, bool)> {
    match e {
        Expr::Var(v) => Some((v.clone(), Vec::new(), false)),
        Expr::TSAnnotated(inner) => extract_path(inner, side),
        Expr::FieldAccess { obj, field } => {
            extract_path(obj, side).map(|(root, mut segs, opaque)| {
                if !opaque {
                    segs.push(field.clone());
                }
                (root, segs, opaque)
            })
        }
        Expr::IndexAccess { arr, idx } => {
            side.push(idx);
            // The chain *above* the index is still named. `theme.snackBar[v].color`
            // reads an unknown member of `theme.snackBar`, so that prefix is the
            // handle the read passes through, and a `[theme.snackBar]` dep covers
            // it exactly as `[x.a]` already covers `x.a.b`. Only the segments
            // *below* the index are lost — `opaque` stops the caller pushing more.
            extract_path(arr, side).map(|(root, segs, _)| (root, segs, true))
        }
        other => {
            side.push(other);
            None
        }
    }
}
```

```rust
fn collect_paths(expr: &Expr, pinned: &HashSet<String>, out: &mut HashSet<AccessPath>) {
    if !pinned.is_empty() && pure_key(expr).is_some_and(|k| pinned.contains(&k)) {
        return;
    }
    match expr {
        // Member chains are read whole by `extract_path` (which peels
        // TSAnnotated and records the maximal chain), recursing only into the
        // off-chain sub-exprs it collects — never a generic child descent.
        Expr::Var(_) | Expr::FieldAccess { .. } | Expr::IndexAccess { .. } => {
            let mut side = Vec::new();

                out.insert(AccessPath { root, segments });
            }
            for s in side {
                collect_paths(s, pinned, out);

        _ => expr.for_each_child(&mut |c| collect_paths(c, pinned, out)),
```

```rust
/// Every path a body reads, resolved against its own local names: an aliasing
/// `let` is skipped (a rename is not a read), paths rooted at an alias are
/// rewritten to what it names, and what is still rooted at a name this body
/// binds is dropped — bound, not free.
///
/// One function for the body and for every nested `FnLit`, because a closure
/// renames things exactly as its enclosing body does.
fn collect_body_paths(cfg: &CFG, pinned: &HashSet<String>, out: &mut HashSet<AccessPath>) {
    let aliases = local_aliases(cfg);
    let mut used: HashSet<AccessPath> = HashSet::new();
    cfg.for_each_expr_where(
        &|s| !matches!(s, Stmt::Let { var, .. } if aliases.contains_key(var)),
        &mut |e| collect_paths(e, pinned, &mut used),
    );
    resolve_aliases(&aliases, &mut used);
    subtract_local_definitions(cfg, &mut used);
    out.extend(used);
}

/// Names this body declares exactly once, as a rename of a member chain:
/// `const condition = performanceCondition`. Nothing else qualifies — a name
/// bound twice is not a rename, and a right-hand side that is anything but a
/// plain chain (a call, an index, an object literal) is a computation whose
/// reads have to be recorded where they happen.
fn local_aliases(cfg: &CFG) -> HashMap<Var, AccessPath> {
    let mut counts: HashMap<&Var, usize> = HashMap::new();
    let mut candidates: HashMap<Var, AccessPath> = HashMap::new();
    for block in cfg.blocks.values() {
        for stmt in &block.stmts {
            let (Stmt::Let { var, rhs, .. } | Stmt::Assign { var, rhs, .. }) = stmt else {
                continue;
            };
            *counts.entry(var).or_default() += 1;
            if !matches!(stmt, Stmt::Let { .. }) {
                continue;

            let mut side = Vec::new();

            // pushes one), but the walk skips this statement wholesale, so an
            // off-chain sub-expression here would be a read lost outright.
            if let Some((root, segments, false)) = extract_path(rhs, &mut side)
                && side.is_empty()
            {
                candidates.insert(var.clone(), AccessPath { root, segments });
            }
        }
    }
    candidates.retain(|v, _| counts.get(v) == Some(&1));
    candidates
}
```

```rust
/// any chain of renames. `{ bump }` records the member as `Var("bump")`, so a
/// chase that stopped at the first right-hand side would see a name where the
/// value is. The same propagation the interpreter does when it binds a
/// right-hand side, and bounded because a certain binding chain is finite
/// anyway.
pub fn binding_of<'c>(var: &str, cfg: &'c CFG) -> Option<&'c Expr> {
    let mut cur = sole_binding_in(var, cfg)?;
    for _ in 0..MAX_ALIAS_HOPS {
        let Expr::Var(next) = cur else { break };
        let Some(deeper) = sole_binding_in(next, cfg) else {
            break;
        };
        cur = deeper;
    }
    Some(cur)
}

/// destructuring preamble); the bound only stops a cycle, and stopping leaves
/// the name itself — which no caller mistakes for a value.
const MAX_ALIAS_HOPS: usize = 8;

/// bound zero times or more than once. Conditional or repeated re-binding is
/// not "some value we haven't found" — it is a name whose captured environment
/// is no longer syntactically certain, so the readers above fail closed.
fn sole_binding_in<'c>(var: &str, cfg: &'c CFG) -> Option<&'c Expr> {
    let mut found: Option<&Expr> = None;

        for stmt in &block.stmts {
            let (Stmt::Let { var: v, rhs, .. } | Stmt::Assign { var: v, rhs, .. }) = stmt else {
                continue;
            };
            if v != var {
                continue;
            }
            if found.is_some() {
                return None;
            }
            found = Some(rhs.peel_ts());

    }
```

```rust
/// One past the largest allocation-site `ExprId` in `cfg`, nested function
/// bodies included — the width of the id range a graft of `cfg` occupies.
///
/// A splice adds this to its running cursor so the next graft lands above it,
/// which is what makes the *same* callee inlined twice two allocation sites.
pub fn alloc_id_span(cfg: &CFG) -> usize {
    let mut max: Option<usize> = None;
    let mut note = |id: ExprId| max = Some(max.map_or(id.0, |m: usize| m.max(id.0)));
    fn walk(e: &Expr, note: &mut impl FnMut(ExprId), depth: usize) {
        if depth == 0 {
            return;
        }
        match e {
            Expr::ObjectLit { id, .. } | Expr::ArrayLit { id, .. } | Expr::New { id, .. } => {
                note(*id)
            }
            Expr::FnLit { id, body_cfg, .. } => {
                note(*id);
                body_cfg.for_each_expr(&mut |inner| walk(inner, note, depth - 1));
            }
            _ => {}
        }
        e.for_each_child(&mut |c| walk(c, note, depth));
    }
    // A `FnLit` body is a CFG of its own; the bound keeps a pathological
    // nesting from recursing without end, and no real body approaches it.
    cfg.for_each_expr(&mut |e| walk(e, &mut note, 64));
    max.map_or(0, |m| m + 1)
}
```

### 4.6 La primitive de splice (`splice_callee_into_cfg`)

- **Positions** (ADR-039 §2) : les `let param = arg` et le `let bound = e`
  prennent `call_span`, la position de l'instruction d'appel ; les

- **Le paramètre sans argument n'est pas lié** (le `zip` de l'étape 4

  l'environnement (§3.12).
- Si `post` est vide (`stmt_idx` hors limites), rien n'est retiré — le code

- Dépendance à la **densité** des ids de l'appelé : si ses ids n'étaient pas

```rust
/// Every variable bound inside `cfg`: `params` plus every `let` target.
/// Assignments to variables never `let`-bound are left out — those are writes
/// to an outer/free binding, not locals.
pub fn bound_vars(cfg: &CFG, params: &[Var]) -> HashSet<Var> {
    let mut bound: HashSet<Var> = params.iter().cloned().collect();
    for block in cfg.blocks.values() {
        for stmt in &block.stmts {
            if let Stmt::Let { var, .. } = stmt {
                bound.insert(var.clone());
            }
        }
    }
    bound
}

/// Fresh-name map for the variables a splice must rename: everything bound
/// inside `cfg`, plus any *free* variable of `cfg` that `caller_bound` also
/// binds.
///
/// The bound half keeps the splice hygienic — a callee local `data` must not
/// clobber a caller `data` in the flat abstract environment.
///
/// The free half is lexical scoping (#141). A callee's free variable resolves
/// in the **callee's** module scope: its imports, its module consts. It can
/// never mean a local of whatever function happens to call it. Leaving those
/// names untouched let the caller capture them, and the capture is silent and
/// wrong in both directions — twenty's `useOpenAskAiPageInSidePanel` reads a
/// `t` it imports from `@lingui/core/macro`, a module binding that cannot
/// change between renders, and inlining it into a component holding
/// `const { t } = useLingui()` made 208 corpus rows claim the import was a
/// hook value that belonged in a deps array.
///
/// Only *colliding* free names are renamed, not all of them. A free name the
/// caller does not bind is still the callee's own, and several of them are
/// recognised by name downstream — `fetch`, `console`, a sibling utility the
/// registry resolves — so renaming those wholesale would trade this false
/// positive for a false negative. When the caller does bind the name, the two
/// are provably different bindings and the callee's must be isolated; that it
/// then resolves to nothing is correct, and a free variable resolving to
/// nothing is already silent.
///
/// `salt` must be unique per splice within the final CFG so two splices of the
/// same callee don't produce colliding fresh names.
pub fn callee_rename_map(
    cfg: &CFG,
    hooks: &[HookEntry],
    params: &[Var],
    salt: u32,
    caller_bound: &HashSet<Var>,
) -> HashMap<Var, Var> {
    let mut rename: HashSet<Var> = bound_vars(cfg, params);
    // `hooks` matters: by this point a `useCallback` in the callee is a
    // `HookEntry` with its own body CFG and only a marker left in `cfg`, so the
    // names it reads — the ones most likely to be captured — are not in `cfg`
    // at all. The same rename map is applied to those sub-bodies, so it has to
    // be built from them too.
    let bodies = std::iter::once(cfg).chain(hooks.iter().filter_map(|h| h.body_cfg()));
    for body in bodies {
        for free in crate::ir::free_vars::compute_free_vars(body) {
            if !rename.contains(&free) && caller_bound.contains(&free) {
                rename.insert(free);
            }
        }
    }
    rename
        .into_iter()
        .map(|v| {
            let fresh = format!("{v}#{salt}");
            (v, fresh)
        })
        .collect()
}
```

Règle de renommage, formellement : pour un appelé de corps `C`, de hooks
`H`, de paramètres `P`, et un appelant liant `B` :

```
R = bound(C, P)  ∪  { v ∈ libres(C) ∪ ⋃_{h∈H} libres(h.body) | v ∈ B }
ρ(v) = v#salt  pour v ∈ R,  identité sinon
```

- Les paramètres et `let` de l'appelé sont **toujours** renommés (même sans
  collision ; exemple §6.2 : `raw` → `raw#0`).
- Une variable libre de l'appelé n'est renommée **que** si l'appelant la lie
  (#141) : elle devient alors une variable libre sans liaison ⇒ ⊤ ou absente,
  « already silent ». Les libres non en collision (`fetch`, `console`, un
  utilitaire frère) gardent leur nom, reconnu par nom en aval.
- `caller_bound` = `bound_vars(render_cfg, &[])` : seuls les `Let` du render
  de l'appelant (pas ses paramètres ni les liaisons de ses corps de hooks).
  Le paramètre `props`/`__p0` du composant n'y est donc pas (à vérifier si
  une collision avec le nom du paramètre de composant est possible : le
  paramètre déstructuré passe par `let __obj_N = __p0`, le nom `__p0`
  n'apparaît pas dans un corps de hook).
- Le renommage est **capture-aware** : en entrant dans un `FnLit`, ses propres

### 4.8 Substitution paramètre → argument (`subst_vars_expr`)

`src/ir/splice.rs:L636-L663`
```rust
/// Substitute variable *reads* with expressions, capture-aware. Unlike
/// `rename_vars_expr` this never touches binding sites — it is the honest,
/// exhaustive replacement for the old hand-rolled `subst_vars` that dropped
/// every composite expression through an `other => other` arm (so a param
/// nested in `useState({x: param})` or `useState(() => param)` never resolved).
pub fn subst_vars_expr(expr: Expr, subst: &HashMap<Var, Expr>) -> Expr {
    if subst.is_empty() {
        return expr;
    }
    match expr {
        Expr::Var(v) => subst.get(&v).cloned().unwrap_or(Expr::Var(v)),
        Expr::FnLit {
            id,
            params,
            body_cfg,
        } => {
            let inner: HashMap<Var, Expr> = subst
                .iter()
                .filter(|(k, _)| !params.contains(k))
                .map(|(k, v)| (k.clone(), v.clone()))
                .collect();
            let owned = Arc::try_unwrap(body_cfg).unwrap_or_else(|a| (*a).clone());
            Expr::FnLit {
                id,
                params,
                body_cfg: Arc::new(subst_vars_cfg(owned, &inner)),
            }
        }
```

Utilisée **uniquement** pour les `init` de `HookEntry::State` d'un hook custom
(`src/engine/fixpoint.rs:1028-1041`) : l'init d'un `useState` est évalué dans
un environnement séparé (consts de module + props), que les `let param =
arg` du splice n'atteignent pas ; on inline donc l'argument concret
(`useState(initial)` → `init = 0`, exemple §6.3). L'ordre est :
`remap_hooks` → `subst_vars_expr` (sur l'init d'origine, noms non renommés)
→ `rename_hook_entry` (renomme ce qui reste). **Défaut (vérifié par la
sonde, non répertorié dans le tracker)** : la substitution ne retire de sa
table que les **paramètres** d'un `FnLit` imbriqué, jamais ses `let`
(`subst_vars_cfg`, `src/ir/splice.rs:755-821`, substitue tous les rhs et
terminateurs sans regarder les cibles). Un local homonyme d'un paramètre du
hook, dans un initialiseur paresseux, voit donc ses lectures remplacées par
l'argument. Reproduction (`/tmp/ircheck/subst`) :

```tsx

  const [c, setC] = useState(() => {
    const p = 1;
    return p;
  });
  return c;
}
// App.tsx
export function C() {
  const c = useCounter("x");
  return <div>{c}</div>;
}
```

donne après expansion (sonde, §6.0) :

```
  hook: State #1 init=Fn#1() {
        B0:
          let p#0 = 1   @fFileId(1):4:10
          -> return "x"
      } @fFileId(1):3:8
```

L'état initial est abstrait par la valeur **exacte** `"x"` alors que le
programme concret vaut `1` : ce n'est pas une sur-approximation mais une
valeur fausse (direction interdite par l'invariant de soundness ; l'ancienne
note de ce dossier la jugeait « sans effet de soundness », c'était inexact).
Le cas est rare (masquage d'un paramètre de hook par un local du thunk). La
correction naturelle, au niveau de la primitive, serait de retirer aussi de
la table les noms `bound_vars(body, params)` du `FnLit` traversé (comme le
fait déjà `compute_free_vars` pour ses `Let`).

Invariants garantis :

- **Labels** : `offset = max+1` ⇒ les labels de l'appelé atterrissent
  au-dessus de tous les labels courants (y compris ceux déjà insérés par une
  expansion précédente).
- **Salts** : un par greffe, monotone dans le composant (partagé par
  l'inlining d'utilitaires, qui passe en premier).
- **Sites d'allocation** : le curseur `next_alloc` part au-dessus des ids
  que `alloc_span` voit et avance de la largeur de chaque greffe (#134, test
  `an_inlined_hook_does_not_take_over_the_callers_allocation_sites`,
  `tests/allocation_site_identity.rs:176`). **Correction (vérifiée par la
  sonde)** : l'invariant « deux greffes ne partagent jamais d'`ExprId` entre
  elles ni avec l'appelant » n'est **pas** garanti. `alloc_span`
  (`src/engine/fixpoint.rs:872-883`) ne mesure que le CFG et les
  `HookEntry::body_cfg()` ; il ignore les expressions portées par les entrées
  **sans corps** — `State.init`, `Ref.init`, `Custom.args` — et les éléments
  de `deps`. Un `ObjectLit` passé en argument à un hook custom (le dernier
  site alloué du composant) peut donc recevoir le même `ExprId` qu'un objet
  d'une greffe ; voir §8.7 pour la reproduction.
- **Provenance** : chaque ligne du hook inliné est ajoutée avec `label +
  offset` et `inlined: true` ; la ligne directe de l'appel au wrapper reste
  (label pendant).
- **Position des findings** : les instructions du hook gardent leurs spans
  (fichier du hook) ⇒ ADR-024 (§4.13).
- **Garde de récursion** : un nom déjà expansé n'est plus expansé *dans ce
  composant* — voir §8 pour la conséquence sur deux appels du même hook.
- Cas défensif (marqueur introuvable, « should not happen ») : greffe du seul
  bloc d'entrée en tête du render et `regions.render_poisoned = true`
  (fail-closed pour la provenance, `src/engine/fixpoint.rs:1079-1109`).

Ordre relatif des passes : `expand_utility_calls` **avant**
`expand_custom_hooks` (`src/engine/fixpoint.rs:200-229`, « so utility bodies
containing hook calls become visible to the hook expansion pass »).
Conséquence : un utilitaire appelé **dans le corps d'un hook custom** n'est
pas inliné (le corps du hook est greffé après la passe d'utilitaires) —
angle mort reconnu par ADR-027 §5 (« utilities inside custom-hook bodies »),
vérifié §8.

### 4.10 Inlining des utilitaires (`inline_in_cfg`, `splice_one_call`)

```rust
/// Splice utility calls in `cfg`. Each utility name is inlined at most once
/// per CFG: this is the recursion guard (self-recursive utilities, and
/// `A → B → A` chains, terminate after a single round-trip; subsequent calls
/// remain `Call` → opaque `Top`).
///
/// `max_depth` caps the total number of splices into one CFG so a single
/// inlining never explodes the IR even with deep utility chains.
fn inline_in_cfg(
    cfg: &mut CFG,
    ctx: &mut InlineCtx<'_>,
    regions: &mut Vec<crate::engine::setters::InlineRegion>,
    expanding: &mut HashSet<String>,
) {
    let mut budget = ctx.max_depth;
    loop {
        let target = find_inlining_target(cfg, ctx.registry, ctx.caller_file, regions, expanding);
        if budget == 0 {
            // Exhausting the budget leaves the remaining calls opaque (⊤) —
            // sound, but a truncation, and one that measurably happens (20 CFGs
            // in the excalidraw corpus, 6 in memos). Record it so the component
            // withholds its assurances instead of publishing `verified:` over
            // utility bodies the analysis never read.
            ctx.truncated |= target.is_some();
            break;
        }
        let Some((block_id, stmt_idx, name)) = target else {
            break;
        };
        // Mark before splicing so a self-recursive call inside the spliced
        // body is skipped on the next scan.
        expanding.insert(name.clone());
```

```rust
    /// Every module reachable from `seeds` through import edges, seeds
    /// included — stopping at, and excluding, any module that declares
    /// `boundary`.
    ///
    /// The boundary argument is the RSC directive rule in one place: a
    /// directive is written once at the top of a module and governs
    /// everything imported below it, so a walk that starts in one environment
    /// ends where the next one is declared. Pass `None` for a plain forward
    /// reachability walk.
    pub fn reachable_from<'p>(
        &self,
        seeds: impl IntoIterator<Item = &'p Path>,
        boundary: Option<&str>,
    ) -> HashSet<PathBuf> {
        let blocked = |p: &Path| {
            boundary.is_some_and(|d| self.files.get(p).is_some_and(|f| f.has_directive(d)))
        };
        let mut seen: HashSet<PathBuf> = HashSet::new();
        let mut queue: VecDeque<PathBuf> = VecDeque::new();
        for s in seeds {
            if !blocked(s) && seen.insert(s.to_path_buf()) {
                queue.push_back(s.to_path_buf());
            }
        }
        while let Some(path) = queue.pop_front() {
            let Some(facts) = self.files.get(&path) else {
                continue;
            };
            for dep in &facts.imports {
                if !blocked(dep) && seen.insert(dep.clone()) {
                    queue.push_back(dep.clone());
                }
            }
        }
        seen
    }
```

## 5. Décisions de conception

### 5.1 ADR du périmètre

**ADR-003 — Dedicated CFG-based IR** (Accepted, 2026-05-29).
Décide : une IR dédiée, inspirée de React-tRace mais **en CFG**, séparée de
l'AST oxc. Justification : un IR arborescent (style React-tRace) exige une
transformation CPS pour les `return` précoces et ne représente pas les
boucles sans arcs arrière ; le CFG représente nativement `return`, boucles,
`switch`, identifie les en-têtes de boucle (widening), permet la dominance
(hooks conditionnels). Alternative refusée : appliquer les fonctions de
transfert sur l'AST oxc (dizaines de formes équivalentes). Écarts avec le
code actuel : ADR-003 renvoie à `docs/ir.md` (**inexistant** dans `docs/`),
décrit des nœuds `UseState`/`UseEffect`/`HookCall` et `TsAnnotated { expr, ty
}` (aujourd'hui : `HookEntry` + marqueurs, et `TSAnnotated` sans type depuis
`45ab9fd`), et un désucrage `a && b` → `If(…)` (aujourd'hui un diamant de
blocs, pas d'expression `If`). La règle d'identification des composants
(priorité `use*` → hook, puis JSX retourné, puis annotation) relève du
dossier 01.

**ADR-004 — Component structure: separate render_cfg + effect_cfg**
(Accepted, 2026-05-29). Décide : un composant = `render_cfg` + table
`hooks`, chaque effet portant son propre CFG ; pas de méta-CFG unique
render→effet→check. Alternative refusée : méta-CFG (graphe énorme, séparation
render/effet implicite, risque de mal modéliser l'ordre React). Argument :
les bugs visés sont des propriétés de l'**état au point fixe**, pas de chemins
d'un graphe unifié. Le squelette `ComponentIR`/`HookEntry` montré est
périmé (pas de `Handler`, `deps: Option<Vec<Expr>>` devenu `DepsArg`, pas de
spans, `file`, provenance).

**ADR-010 — Heap model: allocation-site abstraction** (Accepted —
implemented, 2026-06-03, mis à jour 2026-06-04). Décide : `ExprId` sur chaque
nœud allouant (`FnLit`, `ObjectLit`, `ArrayLit` — puis `New` avec #158),
tas `ExprId → HeapValue`, environnement à deux cartes (`stabs` et `locs`),
`Arc<CFG>` dans `FnLit` pour des clones bon marché, garde de profondeur
`MAX_INLINE_DEPTH = 3`. Alternative refusée : une carte unique `EnvVal = Val
| Loc` (un `extend` écrasait le `Loc` posé par `extend_loc`). Le
« counter in `BlockBuilder` » d'ADR-010 §1 est obsolète : depuis #134 le
compteur est par fichier (`ExprIds`) et le splice décale (`Offsets::ids`).

**ADR-011 — Source ranges + diagnostic notes** (Accepted — implemented,
2026-06-03). Décide : `SourceRange` (`line` 1-indexé, `col`), table
`line_starts` en O(n) + conversion O(log n), `span: Option<SourceRange>` sur
chaque `Stmt` et `HookEntry` (`Option` pour les tests d'IR manuelle),
`prop_spans` sur `NativeElem`, `Note` et `notes` sur `Diagnostic`. À l'époque
`SourceRange` n'avait pas de fichier (limite levée par ADR-019 §1 :
`FileId`), et `prop_spans` était une `HashMap` (aujourd'hui un `Vec`, pour la
taille d'`Expr`).

**ADR-012 — Inter-component analysis architecture** (Accepted, 2026-06-04).
Décide : inlining **descendant** des enfants (le parent analyse l'enfant
avec ses props abstraites), mémoïsation par égalité abstraite des props,
flux bidirectionnel (setters du parent passés en props), store partagé,
détection de racines modulaire, récursion coupée à ⊤. Alternative refusée :
résumés paramétriques ascendants (« sans gain justifié à ce stade »).
Correspondance avec le code : `StateValue::ComponentSetter { component:
Symbol, label }` est devenu `SetterVal::One(ComponentId, HookLabel)`
(`src/domains/impls/setter_val.rs:16-23`), `SharedStateStore` est indexé
par `(ComponentId, HookLabel)` (`src/domains/stores/shared_state_store.rs:15-17`),
`HeapValue::AbstractObject` est devenu `HeapValue::Obj`, `HeapValue::FnLit {
captured }` est `HeapValue::Fn { params, body_cfg, captured }`
(`src/domains/stores/heap.rs:19-29`). La « limite acceptée » « Dynamic
(`const Comp = cond ? A : B; <Comp />`) → `CompApp` not generated » est
inexacte aujourd'hui : un `CompApp { name: "Dyn", origin: None }` **est**
produit mais ne se résout pas (exemple §6.5) ; l'issue wontfix #63 reprend la
formulation d'ADR-012.

**ADR-024 — Finding attribution across inlined hooks** (Accepted,
2026-07-26). Décide : (1) la ligne principale d'un finding **rend l'origine**
quand le fichier de l'ancre diffère du fichier du composant, et le `file` du
JSON devient celui de l'ancre (changement driver uniquement) ; (2) les
findings ne sont **jamais dédupliqués entre consommateurs**, parce que les
faits d'un même corps de hook sous deux sites d'appel sont incomparables
(contre-exemple `useStep(1)` → `infinite-loop`, `useStep(0)` →
`redundant-set-state`, reproduit §6.6) ; (3) attribution correcte ≠
actionnabilité (frontière first-party/dépendance non traitée). Alternatives
refusées : dédup inter-consommateurs (générateur de faux négatifs) ; analyse
unique du hook avec paramètres ⊤ (ni ne subsume ni n'est subsumée) ;
regroupement pour l'affichage *différé* à l'époque — depuis, #129 a introduit
un regroupement par localisation dans le rendu humain (`[in 3 components]`,
§6.6), le JSON gardant une ligne par composant (`docs/limitations.md:232-244`).

**ADR-039 — A synthetic binding is synthetic, its position is not**
(Accepted, 2026-09-02, implémente #131). Décide : (1) tout statement
synthétique prend la position de l'expression qu'il lie (neuf sites de
fabrication : hoist d'`await`, bras de ternaire, opérandes `||`/`&&`,
défauts de déstructuration…) ; (2) ce que la source ne peut nommer, le
splice le nomme par **son site d'appel** (`let param = arg`, `let bound =
e`) ; (3) un corps sans instruction propre hérite de la position par
laquelle on y est entré (paramètre `witness` du parcours des setters) —
héritage en *repli*, jamais en écrasement ; (4) un finding sans position
prend la première position de sa chaîne de témoins (registre des règles).
Alternative refusée : donner un span à `Terminator::Return` (« better by a
line, at the cost of a hundred construction sites ») — laissé en « Not
decided here » (#140). Mesure : 82 findings sans position sur 7 146 → 0,
ensemble de findings inchangé. ADR-027 §4 parlait encore de « span-less
statements (param-binding `Let`s, the return-binding `Assign`) » : ADR-039
les a placés, et le retour est désormais un `Let`.

**ADR-040 — Component identity is an interned id, and the display name is a
rendering** (Accepted, 2026-09-05, implémente #7, **supersede ADR-038 §5**,
garde la clé composite d'ADR-013 §1). Décide : (1) `ComponentId` interné dans
une `ComponentTable` (comme `FileId`/`FileTable`) ; (2) le nom affiché est
frappé au rendu et **rien ne le compare** ; (3) `CompApp` porte `origin:
Option<Arc<CompOrigin>>` (fichier + nom exporté), threadé par `LowerCtx` ;
(4) résolution en un seul lieu (`resolve_child`) qui **refuse de deviner**
(`Ambiguous`) ; (5) une seule orthographe de chemin (`normalize` dans
`lower_files_with`). Alternative refusée : analyser tous les candidats d'un
nom ambigu (sound et plus précis, mais 1 347 références ambiguës dans le
corpus, et la forme du blocage O(C²) de #86) ; le résidu vient surtout des
alias `@workspace/*` non résolus (#48). Mesure : digest identique sur 35 541
fichiers pour le changement d'identité ; 1 317 → 1 348 localisations pour le
changement de résolution. L'issue #7 est encore `OPEN` dans le tracker
(vérifié `gh issue view 7` le 2026-09-28), bien que le commit `806d114`
la cite (« … identity is an id (#7) »).

## 7. Contexte React nécessaire

- **Phases render / commit.** Le corps d'un composant (render) doit être pur ;
  les effets s'exécutent après le commit. L'IR le reflète structurellement :
  `render_cfg` d'un côté, `body_cfg` de chaque `Effect` de l'autre (ADR-004),
  et les handlers en points d'entrée séparés (`Handler`). `EdgeKind::Await`
  marque, **dans** un corps, ce qui s'exécute à un tour ultérieur de la boucle
  d'événements (ADR-035).
- **Règles des hooks.** L'identité d'un hook est son **rang d'appel** ; les
  hooks ne doivent pas être conditionnels ni dans des boucles, et un
  utilitaire (non-`use*`) n'en appelle pas. D'où `HookLabel` positionnel,
  `HookMarker` qui ancre chaque site d'appel dans le CFG (dominance pour
  `conditional-hook`), et `FunctionIR` sans table de hooks. Un hook custom est
  une **abstraction de code** sans état propre : ses hooks deviennent ceux de
  l'appelant, en séquence — c'est exactement ce que fait le splice
  (renumérotation des labels à la suite de ceux de l'appelant).
- **`useState` : batching et updater.** `setX(v)` planifie un nouveau rendu ;
  `setX(prev => …)` lit la valeur courante (voir dossiers moteur/règles). Dans
  l'IR, le tuple donne `StateVal(l)`/`StateSetter(l)` ; `init` peut être
  paresseux (`FnLit`).
- **Comparaison `Object.is` des deps.** React compare **chaque élément** du
  tableau de deps avec `Object.is` ; un spread `[...rows]` compare `rows[0],
  rows[1], …`, jamais `rows` — fondement de `DepsList::covering`. Sans
  tableau (`Absent`), l'effet ré-exécute à chaque rendu ; avec un tableau
  illisible (`Opaque`), il est bien « gated ». Un dep calculé
  (`searchParams.get("sort")`) est comparé par sa valeur, d'où l'épinglage
  (`free_paths_and_pinned`), mais une sérialisation perd de l'information
  (`JSON.stringify(o)` n'épingle pas `o`).
- **Stabilité référentielle.** Un littéral d'objet/tableau/fonction est une
  nouvelle référence à chaque rendu ; `useRef`, `useCallback([])`, une
  constante de module sont stables. D'où `ExprId` (site d'allocation),
  `MarkerVal::StableRef`, `ModuleConstInit::Ref`, `SummaryValue::{StableRef,
  UnstableRef, Shape}`, et `Expr::New` (toujours frais).
- **Strict Mode** : double invocation des rendus et effets en développement
  (setup → cleanup → setup). L'IR ne le modélise pas : aucun type de
  `src/ir/` n'y fait référence, `docs/semantics.md` n'existe pas, et aucune
  ADR du périmètre n'en parle (vérifié par `grep -rli "strict mode"` : seuls
  des scénarios de campagne `docs/campaign/scenarios-*.md` et le dossier 06
  §7.7, qui le traite côté moteur/règles). Le manuscrit peut en parler au
  chapitre moteur, pas au chapitre IR.
- **Server Components.** Les directives `"use client"`/`"use server"` se lisent
  dans le prologue d'un module et gouvernent tout ce qu'il importe ⇒
  `ModuleFacts.directives` et `ModuleTable::reachable_from(…, boundary)`.
- **Context.** `createContext` crée une cellule, `<X.Provider value>` la
  fournit, `useContext(X)` la lit. L'IR identifie la cellule par `ContextId`
  (fichier + nom d'origine) via `ModuleConstInit::Context` ; `useContext`
  lui-même est un `Custom` non modélisé (#28).
- **Variantes d'effets.** `useLayoutEffect` s'exécute de façon synchrone
  après les mutations du DOM, avant la peinture ; `useInsertionEffect` encore
  plus tôt (avant les layout effects, pour l'injection de styles) ;
  `useEffect` après la peinture. Pour les bugs visés (boucles d'état,
  captures périmées), le moment exact ne change pas le point fixe : le
  lowering les réunit en `HookEntry::Effect` (`make_hook_entry`), et seule
  `HookProvenance.origin_hook` garde la distinction pour une règle qui en
  aurait besoin.
- **`props.children`.** En React, les enfants JSX d'un élément composant
  **sont** la prop `children` ; l'IR le reproduit (`CompApp.props` reçoit une
  clé `children`, un `ArrayLit` synthétique `AtLeast(n)`), tandis qu'un
  élément natif garde ses enfants à part (`NativeElem.children`), parce que
  le DOM n'a pas de « prop children » à passer à du code utilisateur.
- **Handlers ≠ rendu.** Une fonction passée en `onClick` n'est pas exécutée
  pendant le rendu : l'IR la laisse comme `FnLit` dans les props (valeur
  créée à chaque rendu, donc instable) **et** la réifie en
  `HookEntry::Handler` (point d'entrée exécuté « plus tard, n'importe
  quand »). `addEventListener` dans un effet donne aussi un `Handler`
  (`subscription_listener`).
- **Un `return` s'évalue même si le résultat est ignoré.** `f();` exécute
  l'expression de `return` de `f` (appels, setters compris) ; seule la valeur
  est jetée. C'est la sémantique que le splice doit préserver (défaut §8.8).
- **Portée lexicale des modules.** Une variable libre d'un hook ou d'un
  utilitaire désigne une liaison **de son module** (import, `const` de
  module), jamais un local de l'appelant ; l'inlining textuel doit donc
  isoler ces noms (#141, et ses deux angles morts §8.4 pour les écritures et
  §8.9 pour les corps de hooks).
- **Sémantique concrète de référence** : ADR-001 adopte React-tRace (Lee, Ahn,
  Yi — OOPSLA 2025), dont le modèle Tree Memory + StepInit → StepEffect →
  StepCheck correspond au cycle du point fixe (ADR-004). ADR-001 renvoie à
  `docs/semantics.md` pour les extensions (deps, memo, callback, ref, objets) —
  ce fichier est **absent** de `docs/` au commit étudié.

## 8. Subtilités, pièges, limites

### 8.1 Défaut observé : collision d'`ExprId` entre fichiers lors de l'analyse d'un enfant

Constaté §6.8(b), non répertorié dans le tracker (recherche `gh issue list
--search "allocation site"` / `"ExprId"` : seul #134, fermé). #134 a rendu
les ids uniques **par fichier** (compteur `ExprIds`) et a décalé les greffes
(`Offsets::ids`) ; mais `eval_comp_app` copie dans le tas initial de
l'enfant les entrées de tas des props (ids du **fichier du parent**,
`src/domains/transfer/state_value.rs:565-573`), alors que l'enfant alloue
avec les ids de **son** fichier, et `Heap::insert` écrase
(`src/domains/stores/heap.rs:41-43`). Quand les deux numéros coïncident,
l'objet de l'enfant remplace la closure du parent ; l'appel `onPick()` ne
résout plus vers un `Fn` et l'écriture du setter du parent disparaît : un
faux négatif en Error, avec la ligne « ✓ no issues found ». Pistes (au niveau
central, cf. CLAUDE.md) : rendre `ExprId` unique à l'échelle du programme
(compteur global au lowering, ou `(FileId, n)`), ou décaler les ids copiés à
l'entrée de l'enfant. À signaler.

### 8.2 Un hook custom appelé deux fois dans le même composant n'est expansé qu'une fois

`expand_custom_hooks` insère chaque nom dans `expanding` après sa première
expansion ; tout `Custom` ultérieur du même nom est laissé en `HookMarker(l,
Unknown)` (doc `src/engine/fixpoint.rs:884-888` : « sound for the rare case of
a hook called twice in the same component (second call stays opaque FN, not
FP) »). Vérifié : `useStep(0); useStep(1)` dans un même composant
(`/tmp/ra-ir-ex/ex_twice.tsx`) ne rapporte que le `redundant-set-state` du
premier appel ; l'`infinite-loop` du second est manqué. Ce n'est pas un
silence : un `analysis-limit` (Info) est émis et 9 assurances sont
suspendues — mais son texte est trompeur (« hook `useStep` was not found in
the registry », alors qu'il y est). Même chose pour `useBag(p); useBag(q)`
(`/tmp/ra-ir-ex/ex_bag.tsx`) : seul le premier est greffé. Conséquence
annexe : le test `an_inlined_hook_does_not_take_over_the_callers_allocation_sites`
(`tests/allocation_site_identity.rs`) affirme dans son commentaire que « the
same hook inlined twice must land in two ranges », mais ne greffe en réalité
qu'une copie (il passe parce que `ids.len() ≥ 5` est atteint avec l'objet
props du `<div>`). Cette limite n'apparaît pas dans `docs/limitations.md`
(seule l'analogue pour les utilitaires y est, #53).

### 8.3 Utilitaires dans le corps d'un hook custom

L'inlining d'utilitaires précède l'expansion des hooks ; un appel d'utilitaire
écrit **dans** un hook custom reste un `Call` opaque après greffe (vérifié :
`bump(setN#0);` dans `/tmp/ra-ir-ex/ex_util_in_hook.tsx`). Angle mort connu
(ADR-027 §5) ; il retire des lignes à la relation des écrivains, sans rendre
incertaine une ligne présente.

### 8.4 Pièges de lecture de l'IR

- `Let` vs `Assign` (§3.4) et l'asymétrie `bound_vars` (Let seulement) /
  `compute_free_vars` (Let et Assign) : une variable seulement **assignée**
  dans l'appelé n'est ni « liée » (donc pas renommée par la moitié
  hygiénique) ni « libre » (donc pas renommée par la moitié #141). Si
  l'appelant lie ce même nom, l'`Assign` greffé écrit dans la liaison de
  l'appelant. En JS, c'est ce qui arrive **si et seulement si** la variable
  est réellement partagée (fermeture lexicale) — ce qui n'est pas le cas
  entre un appelant et un callee de module. **Vérifié par la sonde**
  (`/tmp/ircheck/assign`) : avec `util.ts` = `let mode = "a"; export
  function setMode() { mode = "b"; }` et un composant qui écrit `let mode =
  s; setMode();`, le render après splice contient

  ```
      B0:
        let mode = s   @fFileId(0):5:6
      B1:
        mode := "b"   @fFileId(1):3:2
        mode;   @fFileId(1):3:2
  ```

  soit une écriture **forte** (un `Assign` remplace la valeur) de la variable
  locale de l'appelant par la valeur d'une variable de module de l'appelé :
  abstraitement `mode` vaut exactement `"b"`, concrètement il vaut `s`. Ce
  n'est pas une sur-approximation mais une valeur fausse. Effet observé sur
  `reactant check` : l'`infinite-loop` est toujours rapporté mais pour un
  autre motif (« may store a fresh reference into state `mode` » au lieu de
  « keeps pushing state `s` ») ; un faux négatif n'a pas été exhibé. C'est
  le trou symétrique de #141 (qui ne traite que les **lectures** libres en
  collision) ; non répertorié dans le tracker.
- Après un splice, l'ordre des `BlockId` n'est plus un ordre d'exécution.
  Si l'appel est dans `B0` dont le terminateur branche vers `B1`/`B2`,
  l'étape 10a déplace ces arêtes sur la jointure `J = max+n+1` : on exécute
  `B0 → (appelé) → J → B1/B2`, alors que `B1`, `B2` ont des ids plus petits
  que `J`. La `BTreeMap` garantit un ordre **déterministe**, pas
  topologique ; un parcours qui a besoin de l'ordre d'exécution doit passer
  par `engine::dominance::rpo` (ré-export `src/engine/mod.rs:31`).
- `HookEntry::Custom.binding` n'est pas renommé par `rename_hook_entry` et
  n'est lu nulle part (vérifié par grep, §3.6.1) : champ mort, ne pas s'y
  fier après splice (observé : `binding=Some("ctx")` alors que la liaison
  greffée s'appelle `ctx#0`, §6.8(a)).
- La ligne de provenance d'un wrapper expansé a un label **pendant** (aucune
  entrée `hooks` ne le porte) : toujours passer par son `span`.
- Les `Handler` n'ont pas de ligne de provenance.
- `Offsets::labels` n'a pas d'appelant de production.
- Docs périmées dans le code : `HookEntry::Memo.deps` (« `None` when… »),
  `extract_path` (« collapsed to the bare root »), `is_call_free` (omet
  `NativeElem`), doc de `for_each_child` attachée à `subscription_listener`,
  `Splice` (renvoie à `rename_vars_cfg`), `function_ir.rs`
  (`doOrNot(setX(...))` n'est pas une position inlinée).
- Docs de conception périmées : `docs/ir.md` et `docs/semantics.md` cités
  par ADR-003/ADR-001 n'existent pas ; squelettes d'ADR-004/ADR-010/ADR-012
  antérieurs au code.
- `ExprId::fresh` est un compteur **global au processus** : deux analyses
  dans le même processus (tests en parallèle) obtiennent des ids différents ;
  sans conséquence tant que ces ids ne sont comparés qu'intra-analyse.

### 8.5 Précision vs soundness : où l'IR choisit le côté sûr

| Lieu | Choix | Direction de l'erreur résiduelle |
|---|---|---|
| `DepsList::covering` | un spread ne couvre rien | FP |
| `DepsArg::Opaque` | gated mais illisible | ni ignoré (FN) ni vide (FP massif) |
| `MarkerVal::Unknown` | hook custom opaque = ⊤, pas `undefined` | FP |
| `ModuleConstInit` | genres certains seulement | FP (⊤) |
| `object_member` après spread | ne répond rien | FP |
| `dep_paths` avec index | ne déclare rien | FP |
| `extract_path` usage avec index | garde le préfixe au-dessus | FP limité |
| `certified_fn_binding` | refuse au moindre re-binding | FN compensé par ⊤ |
| splice `Unreachable` | reste coupé | évite un FP **Error** |
| chute en fin de corps | `Return(undefined)` | évite un FN (sortie coupée) |
| `callee_rename_map` (#141) | isole les libres en collision | évite FP ; les non-collisions gardent leur nom (évite FN) |
| `resolve_child` | `Ambiguous` plutôt que deviner | FN signalé par `analysis-limit` |
| `ModuleTable` vide | « pas de preuve » | FN impossible par confusion |

### 8.7 Défaut observé : `alloc_span` ne mesure pas les expressions des hooks sans corps

Ajouté à la relecture ; non répertorié dans le tracker (`gh issue list
--state all --search "alloc_span"` : vide ; `"allocation site"` : #134,
#135, #156 fermés, sans rapport). `SpliceIds::for_component` et chaque
`salt.take(alloc_span(…))` mesurent la largeur d'ids d'un corps par
`alloc_span(cfg, hooks)` :

`src/engine/fixpoint.rs:L869-L882`
```rust
/// The allocation-id width of a body together with the hook table grafted
/// alongside it — they are numbered from one file counter, so they share a
/// range and must be shifted by one offset.
fn alloc_span(cfg: &CFG, hooks: &[HookEntry]) -> usize {
    std::iter::once(crate::ir::alloc_id_span(cfg))
        .chain(
            hooks
                .iter()
                .filter_map(HookEntry::body_cfg)
                .map(crate::ir::alloc_id_span),
        )
        .max()
        .unwrap_or(0)
}
```

`HookEntry::body_cfg()` renvoie `None` pour `State`, `Ref` et `Custom` :
les `ExprId` de `State.init`, `Ref.init`, `Custom.args` (et des éléments de
`deps`) ne sont pas comptés, alors que `remap_hooks` les **décale**
(`src/ir/remap.rs:268-331`) et que les arguments d'un `Custom` finissent dans
le render CFG (`let param = arg`) quand le hook est expansé. Reproduction
(`/tmp/ircheck/alloc/App2.tsx` + `useBox.ts` + `useFoo.ts`) :

```tsx
// App2.tsx
export function C() {
  const el = <div />;            // Obj#0 (props du <div>)
  const box = useBox();          // hook custom : `const o = { v }; return o;`
  const foo = useFoo({ a: 1 });  // Obj#1, dans Custom.args seulement
  return el;
}
// useFoo.ts
export function useFoo(opts) { return opts; }
```

Render après expansion (sonde, extrait) :

```
    B1:
      let v#0 = StateVal(2)   @fFileId(1):3:9
      let o#0 = Obj#1{v: v#0}   @fFileId(1):4:8
      let box = o#0   @fFileId(0):6:8
    …
    B3:
      let opts#1 = Obj#1{a: 1}   @fFileId(0):7:8
      let foo = opts#1   @fFileId(0):7:8
```

Deux littéraux distincts portent le même site `Obj#1` dans **un** CFG :
`next_alloc` valait `alloc_span = 1` (seul `Obj#0` est visible), la greffe
de `useBox` a reçu la plage `[1, 2)`, et l'objet `{ a: 1 }` du composant
avait déjà l'id 1. Le tas abstrait étant indexé par `ExprId` et
`Heap::insert` écrasant (`src/domains/stores/heap.rs:41-43`), c'est
exactement la classe de #134 (« a callee's `ObjectLit` shared a heap entry
with the caller's and answered its member reads »). Une conséquence
observable sur `reactant check` n'a pas été exhibée pendant la relecture (les
variantes essayées étaient déjà muettes sans la collision). Pour
`State.init`, la collision est sans effet sur le tas du rendu : l'init est
évalué avec un tas jetable (`crate::domains::Heap::new()`,
`src/engine/fixpoint.rs:326`). La correction centrale serait que
`alloc_span` parcoure toutes les expressions de la table (`init`, `args`,
`deps`) — par exemple via une méthode « toutes les expressions d'une entrée »
sur `HookEntry`, symétrique de `remap_hook_entry`.

### 8.8 Défaut observé : un appel sans liaison perd l'expression du `return` de l'appelé

Ajouté à la relecture ; non répertorié dans le tracker. Dans
`splice_callee_into_cfg`, le bras `Terminator::Return(ret)` ne pousse le
`let bound = ret` que si `bound_var` est `Some` (`src/ir/splice.rs:158-174`,
extrait §4.6) ; sinon `ret` est **jeté** — ses lectures et ses effets de bord
(appels, setters) disparaissent. `bound_var` vaut `None` pour une
instruction `f(…);` (utilitaire, `splice_one_call`,
`src/engine/fixpoint.rs:1754-1757`) comme pour un hook custom appelé sans
liaison (`find_hook_marker` renvoie `(bid, idx, None)` pour un `ExprStmt`,
`src/engine/fixpoint.rs:1155-1157` ; lu dans le code, non rejoué sur un
hook). Or JS évalue
l'expression du `return` avant de rendre la main : le code dit « the
callee's `Return(e)` value (… `None` to discard as in a bare `f(..);`) »
(`src/ir/splice.rs:37-38`), mais jeter la *valeur* n'autorise pas à jeter
l'*évaluation*. Reproduction (`/tmp/ircheck/ret/`) :

```tsx
// Ret.tsx
function bump(set, n) {
  return set(n + 1);
}
export function C() {
  const [n, setN] = useState(0);
  useEffect(() => {
    bump(setN, n);
  });
  return <div />;
}
```

Corps de l'effet après inlining (sonde) : l'appel du setter a disparu.

```
  hook: Effect #1 deps=Absent @fFileId(0):7:2
      B1:
        let set#0 = setN   @fFileId(0):8:4
        let n#0 = n   @fFileId(0):8:4
        -> jump B2
      B2:
        -> return undefined
```

`reactant check Ret.tsx` : « ✓ 1 file(s) no issues found. » ; la même
fonction écrite `set(n + 1);` (instruction, `Stmt.tsx`) donne `warn
infinite-loop [hook:0] (line 7:2) this effect keeps pushing state `n` …`.
C'est un **faux négatif** accompagné du « ✓ » réservé aux runs complets.
Correction centrale naturelle : quand `bound_var` est `None`, pousser
`Stmt::ExprStmt(ret, call_span)` au lieu de rien (comme le fait déjà le
lowering pour `void e`, `src/lowering/expr_lower.rs:229-232`). (Observation
annexe, hors périmètre IR : `const r = bump(setN, n);` garde bien l'appel —
`let r = set#0((n#0 Add 1))` — mais n'est pas rapporté non plus ; la même
chose vaut pour `const r = setN(n + 1);` écrit directement dans l'effet : la
règle ne semble compter que les appels de setter en position d'instruction.
À instruire côté règles.)

### 8.9 `caller_bound` ne voit que le corps greffé, pas la portée lexicale englobante

`splice_one_call` calcule `caller_bound = bound_vars(cfg, &[])` sur le CFG
**où** l'on greffe (`src/engine/fixpoint.rs:1766`) ; pour un utilitaire
appelé dans un corps d'effet, c'est le corps de l'effet, qui ne contient pas
les `let` du render qu'il capture. La protection #141 (renommer une libre de
l'appelé que l'appelant lie) ne s'applique donc pas aux liaisons **du
render** vues depuis un corps de hook. Observé (`/tmp/ircheck/cap2/`,
`util.ts` = `import { LIMIT } from "./k"; export function lim() { const v =
LIMIT; return v; }`, composant `C({ LIMIT })` appelant `lim()` dans le render
**et** dans un effet) :

```
  render : let v#0 = LIMIT#0   @fFileId(1):3:8     ← isolée (#141)
  effet  : let v#1 = LIMIT     @fFileId(1):3:8     ← capture le prop `LIMIT`
```

Dans l'effet, la lecture de l'import `LIMIT` de `util.ts` devient une
lecture de la prop `LIMIT` du composant. Aucun finding parasite n'a été
observé sur ce cas (`reactant check` : « no issues found ») ; la divergence
reste une lecture fausse au niveau IR, du même type que celle que #141 a
corrigée pour le render. Même remarque pour `expand_custom_hooks`, qui
utilise `bound_vars(render_cfg, &[])` (`src/engine/fixpoint.rs:1019`) : les
paramètres du composant (`props`, `__p0`) n'y figurent pas, mais le
déstructurage passe par des `Let` (`let x = __obj_N.x`) qui, eux, y sont.

## 10. Plan pédagogique suggéré

Prérequis : dossier 01 (lowering/détection) pour savoir **d'où** vient l'IR ;
notions d'interprétation abstraite (treillis, point fixe) seulement pour §4.5
et §4.11. Le chapitre IR peut précéder le chapitre moteur : il n'a besoin que
de l'intuition « l'environnement est une carte nom → valeur abstraite ».

Ordre d'exposition proposé :

1. **Pourquoi une IR** (ADR-003) : un programme React (§6.1), les formes
   équivalentes de l'AST, le choix du CFG. Schéma : le pipeline §1.1.
2. **Le squelette** : `CFG`, `BasicBlock`, `Terminator`, `EdgeKind`, `Stmt`.
   Schéma : le CFG du compteur (§6.1) dessiné en boîtes. Exercice : dessiner
   le CFG d'un `for` avec `break` et d'un `a && setX()`.
3. **Les expressions** : `Expr` par familles (littéraux, allouants, accès,
   opérateurs, appels, JSX, valeurs de hooks). Insister sur `for_each_child`
   exhaustif (exercice : ajouter un variant fictif et lister ce qui casse).
4. **Les hooks** : `HookEntry`, labels positionnels (règle des hooks),
   `HookMarker`/`MarkerVal`, `DepsArg`/`DepsList`/`Arity`, provenance.
   Exercice : prédire `DepsArg` pour `[a, , ...b]`, `deps`, rien, `[a] as const`.
5. **Unités et identités** : `ComponentIR`/`HookIR`/`FunctionIR`,
   `ModuleConstInit`/`ContextId`, `ModuleFacts`, puis `FileId` et `ComponentId`
   (même patron d'internement). Schéma : le triangle `CompOrigin ↔ ComponentId
   ↔ display_name` ; exemple §6.7. Exercice : pourquoi indexer par
   `display_name` casse quand on ajoute un fichier (test
   `interning_a_namesake_changes_…`).
6. **Positions** : `SourceRange`, `SourceMap`, ADR-011 → ADR-019 → ADR-039.
   Exercice : trouver dans §6 les statements `@-` et dire lesquels relèvent de
   #140.
7. **Analyses syntaxiques** : variables libres, chemins, épinglage,
